# GENIUS: Feedback and writing self-efficacy

## Theoretical focus

Following Bandura (1997), self-efficacy concerns beliefs about one's capability
to perform actions needed to achieve a particular outcome. Writing self-efficacy
therefore concerns perceived capability to produce effective writing.
This benchmark examines how feedback experiences relate to writing self-efficacy
depending on learners' achievement goals and initial writing competence,
using the experiment reported by Jansen et al. (2026).

Agents first write an argumentative baseline text. A trained text-scoring model
estimates their initial writing competence from that text. They then complete
a second writing task with five feedback-and-revision cycles and report their
writing self-efficacy. The contribution contains this single protocol.

Bandura, A. (1997). *Self-efficacy: The exercise of control*. W. H. Freeman.
Author's bibliography: https://www.albertbandura.com/albert-bandura-self-efficacy.html

Jansen, T., Pünjer, H., Tanz, M., Schaller, N.-J., & Höft, L. (2026).
For Whom Does AI Feedback Support Writing Self-Efficacy? The Role of Students’
Achievement Goal Orientation and Writing Skills. *Psychologie in Erziehung und
Unterricht, 73*, 153–169. https://doi.org/10.2378/peu2026.art12d

## Participant procedure

Each persistent participant completes 23 administrations:

1. Original pre-task questionnaires, including writing self-efficacy and
   achievement goals. These responses are generated by the agent.
2. The original five-field baseline writing task, with its source graphics.
   A frozen text-scoring model converts the completed essay into an estimated
   baseline writing-competence score. That score remains evaluator-side.
3. The original intermediate questionnaire.
4. Five cycles of drafting, feedback or control instruction, feedback ratings,
   and revision: introduction, pro argument, contra argument, pro argument,
   conclusion. The participant retains its own writing history.
5. Holistic revision, reflection, and the four original T3SE self-efficacy items
   on the 1–5 scale, before later comparison/summative-feedback phases.

The control instruction is: “Nimm dir jetzt die Zeit, deinen Textabschnitt
nochmal zu überarbeiten.” Each feedback call receives the current section,
its draft and the task. It uses a fresh context. Images are supplied as
checksum-verified PNG content. Protocol order and runtime upper bounds are
implemented; actual human writing exposure is a source-fidelity limitation.

## Three separate models and roles

| Component | Implementation | Information received |
| --- | --- | --- |
| Participant | Model selected explicitly for each run | Original materials and the participant's own accumulated session |
| Feedback | Explicitly selected model; fresh context for each feedback event | Current section draft and task only |
| Baseline text scoring | Frozen Ridge regression combining word/character TF-IDF and length features; scikit-learn 1.8.0 | Baseline essay only |

The text scorer was trained against existing automated baseline WLE scores.
Nested cross-validation used 757 student texts from 50 observed classes,
holding entire classes out of training and selecting regularization within
inner class-held-out folds. Results: Pearson r=.7939, Spearman r=.7508,
R²=.6300, MAE=.3700 WLE, RMSE=.4835. Twenty-two missing WLEs and a separate
22 missing class labels were excluded. The final scoring model is frozen and
its checksum is verified before use.

The original study combined ten analytical indicators in a partial-credit/TAM
model. The present direct-WLE scorer is a methodological adaptation. Its
agreement is measured against prior automated WLEs; independent human-gold and
generated-text agreement remain open validation questions.

A paired complete-case downstream sensitivity compared original WLEs with
out-of-fold scorer predictions in the same analysis samples. All 24 primary/CR2
significance classifications agree. Coefficients can change materially: the
mastery three-way coefficient changes from −.0864 to −.1307. The full estimates
and method scope are retained in `source/scorer/inference_sensitivity.json`.

## Reference findings and statistical model

The benchmark compares 801 human cases with 801 planned agent participants:
395 control and 406 feedback in each sample, with the same allocation blueprint.
The human reference is the frozen source-method re-analysis of those 801 cases,
recorded in `source/matched_reference.json`. All 24 selected primary/CR2 tests
are retained, including null findings, across mastery, performance-approach,
performance-avoidance and work-avoidance goals. The evaluator compares
original-scale regression coefficients and inference under the published model:

`post_self_efficacy ~ feedback * initial_writing_competence * achievement_goal + pre_self_efficacy + (1 | class)`

The source-method implementation uses substantive-model MDMB imputation with
5,000 burn-in steps, 10,000 total iterations and 20 imputations, then a random-
intercept outcome model and separate CR2 inference. Four full source fits and
four known-class sensitivities are retained. Fresh imputation runs recover the
central inferential patterns; exact rounded coefficient agreement and multichain
convergence certification are separate unresolved questions.

The following published values provide article context; the executable
comparison uses the recalculated 801-case reference instead.

| Goal | Feedback × goal B / p | Feedback × goal × initial competence B / p |
| --- | --- | --- |
| Mastery | +0.012 / .706 | −0.081 / .046 |
| Performance approach | −0.059 / .034 | −0.024 / .515 |
| Performance avoidance | −0.087 / .001 | −0.015 / .673 |
| Work avoidance | −0.032 / .297 | −0.008 / .824 |

The mastery three-way term has published CR2 p=.151. The main feedback
coefficient is conditional at centered covariates. Nonsignificance is distinct
from equivalence. Hypotheses were not preregistered, and independent replication
of these findings remains an evidence question.

## Matched comparison sample and source provenance

Both sides of the benchmark use N=801 (395 control, 406 feedback). The human
reference uses all available analysis cases, derived from 889 original cases
after five response-pattern exclusions and 83 missing baseline essays.
The 805 cases reported in the article are retained only as a bibliographic
source discrepancy; they are not the reference sample used for scoring.
Raw class information identifies
50 classes and 22 missing class labels; source analysis pools those missing
labels under an extra code, whereas the paper reports 47 classes. The original
instrument and code analyze 16 goal items, whereas the paper describes twelve.
These discrepancies are preserved for reviewer inspection.

All 779 nonmissing original baseline WLEs match the recovered TAM object, and
28 common item fields agree across the survey and analysis sources. Original
values are evaluator reference evidence; participants produce their own texts
and questionnaire responses in this protocol.

## Verification and execution

The package passes its adapter tests and the official structural verifier.
It is discoverable by the actual frozen HumanStudy loader and BaseStudyConfig
interface. End-to-end technical checks cover all 23 administrations, baseline
text scoring, original response scales and condition-specific feedback. These
are execution checks. Full reference comparison requires all 801 planned unique
slots. If observed scores are constant or entirely missing, the evaluator
returns `not_estimable` with variable-level diagnostics and no inferential tests.

From this study directory:

```bash
python -m pytest scripts -q
python scripts/run_study.py
```

The second command exercises the protocol with explicit developer fixtures.
For model execution, choose both models and configure the provider key locally:

```bash
python scripts/run_study.py --live --model PARTICIPANT_MODEL --feedback-model FEEDBACK_MODEL --limit 2 --output /absolute/path/to/new-run
```

The OpenAI-compatible provider path uses `GENIUS_API_KEY` and optionally
`GENIUS_API_BASE`. Omit `--limit 2` for the complete planned sample. Dependencies
are listed in `requirements.txt` and `source/dependencies.json`. The evaluator
keeps diagnostic runs separate from full reference comparisons.
